02

Review in Google

The new tab may briefly show a loading or “not found” page while Google provisions your copy — don’t close it. (A dialog quoting “This report isn’t shared with you” is not that flicker; see below.) Looker Studio then shows an acknowledgement dialog. It appears because you’re about to create a data source that runs a SQL query this page supplied — read the exact query. The dialog lists that query, your billing project, and that the new data source initially uses Owner’s Credentials; nothing is created until you acknowledge it. The query reads only your table, using the opener’s credentials, in your billing project.

03

Save, then secure sharing

Choose “Edit and share” to save it. Before sharing, set the new data source’s credentials to Viewer’s Credentials so every viewer must have their own BigQuery access.

“This report isn’t shared with you” is not a setup error. That dialog is terminal — it offers Reload / Return to report list / Go to report template and does not resolve by waiting. It means the shared dashboard template is unavailable to the Google account signed in to that tab; nothing is wrong with your project, dataset, table, IAM setup, or the identifiers you entered. First confirm the tab is using the account you intend (Looker Studio uses the browser’s default Google account). If you are signed in with an organization-managed account, your own organization’s sharing policy can also block receiving Looker Studio assets from external domains — try a personal account if you can. If the dialog still persists, the template’s copy path is blocked — report it on issue #445 — say only whether the signed-in account is personal or part of an organization; do not post the account’s email address. The repository’s CLI preflight can still validate your table, but it copies the same template, so it is not a workaround; while the template is blocked, use the Grafana dashboard.
Keep the new report private until the credential check. The Linking API creates a data source owned by the person opening the link and its review dialog can show Owner’s Credentials. Before you share the new report

The Linking API creates a new data source owned by the person who opens the link. Keep the report private until these checks pass.

  1. Select Edit and share to save your copy.
  2. Keep the report private while configuring its data source.
  3. Open Resource → Manage added data sources → Edit.
  4. Set Data credentials to Viewer’s Credentials.
  5. Test the report with an account that has only viewer access.
